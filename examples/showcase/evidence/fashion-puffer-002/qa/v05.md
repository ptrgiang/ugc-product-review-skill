## What improved

The clip is therefore stronger as a **production try-on motion** than as a **literal first-frame-state test**.

## Root cause

The primary failure is a generation-mode/input mismatch.

The prompt requested:

```text
literal partial-worn first frame
```

but the workflow supplied only product/creator references plus text. No actual partial-worn start-frame image was used as frame 1.

Therefore:

```text
text describing a first frame
!=
actual first-frame conditioning
```

The asymmetric one-arm-in / one-sleeve-empty state is also a transitional clothing state that the model tends to reconstruct from a more common unworn state when it is not visually fixed.

## Repair direction

Split V06 into two independent experiments instead of combining objectives:

### V06A — true start-frame lock

Use a real supplied partial-worn image as the literal image-to-video first frame. Test only whether that state is preserved and the left arm can complete the sleeve insertion.

### V06B — production-optimized try-on

Do not require an artificial literal partial-state opening. Allow a very short natural setup and optimize for readable, physically plausible left-sleeve insertion plus a clean final fit proof.

These branches must use different pass criteria. V06A measures state preservation; V06B measures production usability.

## Reusable lesson for the skill

When an exact intermediate state matters, the skill must distinguish:

```text
reference image
text-described start state
actual image-to-video first frame
```

Do not label a test as first-frame conditioning unless the generation workflow actually receives and preserves that image as frame 1.
